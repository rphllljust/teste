# CISNE — Workspace inventory and acceptance boundary

The source-derived JSON emitted by node scripts/audit-enterprise-workspaces.mjs --strict enumerates exactly the files that match the workspace naming convention in app/ and validates their imports, rendering references and navigation labels. In the reference candidate this is **27 components, 26 menu destinations**. Five components are contextual/embedded (BillingPreparation, MeasurementPreparation, OrderNextcrmDocuments, OrderPreparation, ServiceOperationsAgenda); Inventory/MRP share one navigation destination and must be tested on their respective tabs. A menu screenshot cannot certify those scenarios.

Each record has distinct source flags (grid, object page, forms, filters, actions and API prefixes) and explicit UNTESTED values for authorization, persistence, visual breakpoints and business journey. Only independently reviewed browser evidence at the **deployed** SHA may change those labels. Neither a Fluent import nor a static pattern is enterprise acceptance.

The independent workflow Enterprise authenticated staging audit requires a high-entropy passphrase supplied only through GitHub's staging environment secret CISNE_STAGING_PASSPHRASE, paired to the Railway staging login hash, and a deployed commit SHA entered at dispatch. It verifies the server-reported SHA and the signed HttpOnly login before any screenshots. Its 26 menu scenarios target desktop, tablet and mobile and require real APIs, without route mocks, including a separate persisted client Object Page test. No screenshots from an unauthorized response are published. Running the ordinary quality browser suite does **not** execute this gate or satisfy it.

Do not change or expose production identity secrets. Staging login remains an operator-only pilot with no MFA, rate limiter or full identity provider; it is not production IAM. The test currently does not mutate data or certify transaction persistence. The isolated PostgreSQL integration suite is the separate transaction layer with cleanup, and a real end-to-end business write journey remains NO-GO until approved isolated data and cleanup have been verified.
